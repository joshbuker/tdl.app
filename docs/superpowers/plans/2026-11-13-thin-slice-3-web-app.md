# Thin slice, plan 3: web app — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the web app end to end: the sync and server groundwork decided on 2026-11-13 (field limits, per-operation push checks, size-based batching, protocol versions, the stuck status, first-message websocket auth, the Inbox repair); a framework-free app core; SQLite on the device; a Quasar web app generated by Quasar's own tools and served by the server; Playwright acceptance tests; and the homelab deployment for the browser demo. Android and Electron are plan 4, which reuses all of this.

**Architecture:**
- **`@tdl/device-store`** implements `ReplicaStore` once, with Drizzle over a tiny `SqlDriver` interface. Each platform supplies only a driver: SQLite Wasm in a worker on the web (this plan), Capacitor and Electron in plan 4, `node:sqlite` in tests.
- **`@tdl/app-core`** holds every app behavior that isn't drawing: the server API client, starting up, logging in and out, the logout warning, session expiry and revocation. It's plain TypeScript, tested headlessly against the real server.
- **`apps/client`** is the Quasar app, generated with `create-quasar` and kept thin: components read reactive snapshots of the app core and `Replica`, and call their methods.
- **The server** serves the built web app from its own origin, so the browser uses the session cookie. Every API route moves under `/api`.

**Tech Stack:** create-quasar 5.0.37, quasar ^2.35.4, @quasar/app-vite ^3.10.4, Vue 3.5, vue-router 5, Pinia 4 (from the generator; unused unless a task needs it), vue-i18n 11 with JSON locales and @intlify/eslint-plugin-vue-i18n 4.5, @sqlite.org/sqlite-wasm 3.54 (`opfs-sahpool` VFS in a worker), drizzle-orm `1.0.0-rc.5` (`sqlite-proxy`), Node's built-in `node:sqlite` (tests), @fastify/static, @playwright/test **1.64.1**, the Quasar MCP server (`@quasar/mcp`).

**Spec:** `docs/superpowers/specs/2026-11-10-thin-slice-design.md`. Behavior comes from:
- the feature specs named in each task, notably `features/app/version-compatibility.md`, `features/app/offline.md`, `features/account/login.md`, `features/tasks/create-task.md`;
- `docs/design-decisions/`, notably `live-update-authentication.md`, `protocol-versions.md`, `server-side-sessions.md`, `vue-and-quasar.md`, `drizzle.md`, `translations-from-day-one.md`, `error-contract.md`;

## Global Constraints

- **Plans 1 and 2's constraints still hold:** Node 26 inside `nix-shell`; AGPL-3.0-only, ESM, private packages; `.ts` relative imports; the licence check and `PINS.md`; no recursion over the graph; domain and sync code return codes and IDs, never English; acceptance files named `*.acceptance.test.ts` with `describe('<spec H1>')` and `test('<scenario H3>')` exactly; `@tdl/domain` does no I/O; `@tdl/sync` depends only on `@tdl/domain`, `zod` and `uuid` and uses no platform globals in its types; no domain rule written twice; the server reads only metadata to route and authorize.
- **New packages follow the existing ones:** `packages/<name>` with `"exports": { ".": { "tdl-compiled": "./dist/index.js", "default": "./src/index.ts" } }`, a `build` script, a `tsconfig.json` referenced from the root `tsconfig.json`, and a Vitest project.
- **`@tdl/app-core`** depends only on `@tdl/domain`, `@tdl/sync` and `zod`, and uses no Vue, Quasar, DOM or Node APIs. `@tdl/device-store` depends only on `@tdl/sync` and `drizzle-orm`.
- **The Quasar app is generated, not hand-written:** `create-quasar` for the app. Quasar CLI commands for anything else they generate. Generated files are committed as generated, before any edit, in their own commit.
- **Use the Quasar MCP server** (`search_docs`, `get_api`) to check a Quasar component's props, events and slots before using it, rather than guessing from memory.
- **No logic in components:** a `.vue` file may format and call app-core, `Replica` or domain functions, but decides no rule (access, validation, graph, sync, session).
- **Every user-facing string goes through vue-i18n,** from `apps/client/src/i18n/en-US.json`. `@intlify/vue-i18n/no-missing-keys` and `no-unused-keys` are errors.
- **Protocol version:** `PROTOCOL_VERSION = '1.0'`, sent and answered in the `TDL-Protocol` header.
- **Field limits:** titles (tasks and lists) at most 500 characters, notes and link reasons at most 100,000, counted in code points, reported as `too-long`.
- **Pins:** `@playwright/test` at exactly `1.64.1`, the version of nixpkgs' `playwright-driver` (its browsers are used in `nix-shell`); lift when nixpkgs updates it. The client's `typescript` matches the root's `6.0.3`.

## Review Focus

1. **A second browser tab.** The `opfs-sahpool` database can be open in one tab only. A second tab must say the app is open in another tab and wait, never open a second copy of the database or corrupt it (Task 12).
2. **A session that ends while edits are being saved.** Editing during the session-expired dialog keeps every change, and logging back in as a *different* user must not push the first user's queued changes under the second user's session (Task 10).
3. **Reloading the web app with unsynced changes,** offline or with an expired session. The tasks and the queued changes are still there after the reload, and nothing is pushed twice (Tasks 9, 10 and 12).
4. **A push whose operations are huge.** 20 tasks with 100,000-character notes go out in several batches, each under the server's 1 MiB limit, and all are accepted (Task 3).
5. **A websocket that never authenticates.** It's closed after 5 seconds, gets no feed message before that, and a client opening many such sockets from one address is capped (Task 6).

- Produces, in `@tdl/sync`:

  - `parseProtocolVersion(value: string): { major: number; minor: number } | null` (`/^(\d+)\.(\d+)$/`).
  - `compareProtocol(app: string, server: string): 'ok' | 'app-outdated' | 'server-outdated'`: server major above the app's gives `app-outdated`; server major two or more below gives `server-outdated`; otherwise `ok` (one major below is the "previous major" support that a 2.0 app will implement).

### Task 6: Live-update authentication

Implements `docs/design-decisions/live-update-authentication.md`.

**Files:**
- Modify: `apps/server/src/config.ts`, `apps/server/src/routes/sync-ws.ts`, `apps/server/src/session-sockets.ts`, `apps/server/src/auth.ts` (sign-out closes sockets), `apps/server/src/app.ts` (CORS), `apps/server/test/ws.test.ts`, `docs/self-hosting.md` (new setting)

**Interfaces:**
- Produces, in the server:
  - Config `APP_ORIGINS`, comma-separated, default `https://localhost,capacitor://localhost`: `config.appOrigins: string[]`.
  - Handshake: with a session cookie, the `Origin` must be the server's own (else 403), and the session must be valid (else 401, as today). Without one, the `Origin` must be absent, the server's own, or in `appOrigins` (else 403); the socket opens unauthenticated.
  - An unauthenticated socket sends nothing and accepts only `{ "type": "auth", "token": string }`. A valid token (checked like a bearer header, via the session guard) authenticates it: tracked by session, sent the latest feed ID. Anything else, or nothing within `WS_AUTH_TIMEOUT_MS = 5000`, closes it with `WS_AUTH_FAILED_CLOSE = 4403`. At most `MAX_UNAUTHENTICATED_PER_ADDRESS = 10` unauthenticated sockets per client address; the 11th is closed with 4403 at once.
  - The `Authorization` header is no longer read on the websocket.
  - Every `WS_RECHECK_MS = 30 * 60 * 1000`, each authenticated socket's session is checked again: revoked closes it with 4401, ended any other way with 4403.
  - A successful `POST /api/auth/sign-out` closes that session's sockets with 4403.
  - CORS: `origin: [config.origin, ...config.appOrigins]`, `credentials: false`, `allowedHeaders: ['content-type', 'authorization', 'tdl-protocol']`, `exposedHeaders: ['tdl-protocol', 'set-auth-token']`.
- Produces, in the transport: with a `token`, the socket opens without headers and sends the auth message on `open`. Close 4403 stops reconnecting and wakes `onFeed(lastId)`, like 4401, so the `Replica` syncs and learns why. `WebSocketLike` loses its `init` argument.

### Task 9: `@tdl/device-store`: SQLite storage for every device
