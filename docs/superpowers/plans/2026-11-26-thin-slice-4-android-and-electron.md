**Goal:** Run the web app's code as an Android app (Quasar's Capacitor mode) and a desktop app (Quasar's Electron mode), each with its own SQLite driver and OS-protected session token, against the same server, and walk the phone and desktop parts of the demo checklist on an Android emulator and the Electron app.

**Architecture:**
- **Almost nothing above the platform changes.** `@tdl/app-core`'s `AppController` already supports token platforms, and `@tdl/device-store` already runs on any `SqlDriver`. Each new app supplies a `Platform` (from `@tdl/app-core`) and a `SqlDriver` (from `@tdl/device-store`), chosen at build time by Quasar's mode flags. The app core gains two fixes for token platforms (Task 3): it never sends `credentials: 'include'` from them, and it saves a token only once `me()` has succeeded.
- **Android:** `@capacitor-community/sqlite` behind a `SqlDriver`, and the session token in `@aparajita/capacitor-secure-storage` (Android Keystore). The app runs at `https://localhost`.
- **Desktop:** the window loads the app from a private `tdl://app` scheme, so it has a real origin. SQLite (`node:sqlite`) and the token (`safeStorage`) live in Electron's main process, reached through a typed IPC layer that only answers the app window's main frame. One instance at a time.
- **The server** trusts the apps' origins for sign-in and sign-up (Better Auth's first-login CSRF check refuses them today), adds `tdl://app` to `APP_ORIGINS`, and checks `Origin` itself on sign-up and every sign-in route, because Better Auth's username sign-in doesn't.
- **Where the apps find the server:** a build-time `TDL_SERVER_URL`, passed as `AppController`'s `baseUrl`. "Choose a server" stays a later feature. While the homelab is down, the emulator reaches the laptop's server through `adb reverse tcp:3000 tcp:3000` at `http://localhost:3000`, which browsers treat as secure. A real phone over HTTPS joins the deferred homelab check.
- **Install roots:** Quasar keeps `apps/client/src-capacitor/` and `apps/client/src-electron/` as their own pnpm install roots, and re-creates their `pnpm-workspace.yaml` and re-installs on every build if they're missing. So each stays its own root, with the root's dependency-safety settings copied into its workspace file and its own committed lockfile, and the licence and audit checks cover it.

**Tech Stack:** Capacitor 8 (`@capacitor/core`, `@capacitor/android`, `@capacitor/cli` ^8.6), `@capacitor-community/sqlite` ^8.1.1 (MIT), `@aparajita/capacitor-secure-storage` ^8.0.1 (MIT), Android SDK through nixpkgs' `androidenv` (compile and target API 36, minimum 24, JDK 21), the Android emulator (x86_64 `google_apis` image, KVM). Electron **45.3.4** (nixpkgs' version; Node 24.22, SQLite 3.54.1 through `node:sqlite`, checked 2026-11-26 and 2026-11-28), Quasar's Electron mode with `@electron/packager`, Playwright's Electron support (`_electron` from `@playwright/test` 1.64.1).

**Spec:** `docs/superpowers/specs/2026-11-10-thin-slice-design.md` (goals: the shared packages run unchanged on Android and in Electron; demo checklist items 1 to 5, 7 and 8 on the phone and desktop. Item 6 needs bob's device offline while alice's stays online: locally only the emulator can go offline on its own, and it's alice's device here. Item 6 passed in the browser in plan 3, and runs on the real phone in the homelab check). Behavior also comes from:

## Global Constraints

- **Plans 1 to 3's constraints still hold:** Node 26 inside `nix-shell`; AGPL-3.0-only, ESM, private packages; `.ts` relative imports; the licence check and `PINS.md`; acceptance files named `*.acceptance.test.ts` with `describe('<spec H1>')` and `test('<scenario H3>')` exactly; no logic in components; every user-facing string through vue-i18n; `@tdl/app-core` uses no Vue, Quasar, DOM or Node APIs; `@tdl/device-store` depends only on `@tdl/sync` and `drizzle-orm`.
- **Generated, not hand-written:** `quasar mode add capacitor`, `quasar mode add electron`, and `cap add android` (run by Quasar's first Android build). Each generator's output is committed untouched, in its own commit, before any edit. Generators run without a terminal fall back to defaults, so pass every answer as a flag.
- **Use the Quasar MCP server** for Quasar's Capacitor and Electron docs (`search_docs`, `get_page`) before configuring either mode.
- **Platform code stays at the edges:** `apps/client/src/platform/<web|capacitor|electron>/` in the window, `apps/client/src-electron/` in Electron's main process. Each platform's logic (row mapping, transactions, path checks, sender checks, SQL checks, token rules) sits in a module with no Electron or Capacitor import, so Vitest tests it with fakes; the files that import `electron` or a Capacitor plugin only wire those modules up.
- **Native code is reached only through dynamic imports guarded by Quasar's flags** (`import.meta.env.QUASAR_CAPACITOR_MODE`, `QUASAR_ELECTRON_MODE`), so the web build contains none of it.
- **IDs and names:** Android `appId` `app.tdl`, app name `TDL App`. Desktop scheme `tdl`, host `app`: the window's origin is `tdl://app`. The Capacitor database is named `tdl-app`; the desktop one is `tdl-app.sqlite3` in `app.getPath('userData')`.
- **Server address:** `import.meta.env.TDL_SERVER_URL` in native builds (from `TDL_SERVER_URL` at build time, default `https://tdl.app`); the web build keeps `location.origin`. Either way it's `AppController`'s `baseUrl`, and the platforms' transports use the `baseUrl` they're given.
- **`APP_ORIGINS` default:** `https://localhost,capacitor://localhost,tdl://app`. Origins are compared as exact strings after `normaliseOrigin` (trim, drop one trailing `/`, lower-case scheme and host): `new URL(x).origin` is `"null"` for `capacitor:` and `tdl:` URLs, so it must not be used to normalise them.
- **Token platforms never send `credentials: 'include'`.** The server's CORS is `credentials: false`, so a credentialed cross-origin request fails its preflight.
- **New dependencies** follow `docs/design-decisions/dependency-safety.md`: pnpm installs only versions at least 7 days old, so ranges resolve to the newest such version (e.g. Capacitor 8.6.2 until 8.6.3 is a week old on 2026-12-04), and anything added beyond what this plan names is compared with `pnpm stats:packages` first. Every nested install root (`apps/client/src-capacitor`, `apps/client/src-electron`) has `minimumReleaseAge`, `storeDir` (the repository's `.pnpm-store`) and `allowBuilds` in its own `pnpm-workspace.yaml`, a committed lockfile, and is covered by `check:licences` and CI's `pnpm audit`.
- **Pins:** npm `electron` at exactly nixpkgs' version (`45.3.4`, released 2026-11-17, so old enough to install), in `apps/client/src-electron/package.json`, because Quasar runs Electron from there and `shell.nix` runs nixpkgs' Electron in its place (Electron's own download doesn't run on NixOS). Record it in `PINS.md`, with the check `nix-instantiate --eval -E '(import (fetchTarball "https://channels.nixos.org/nixos-unstable/nixexprs.tar.xz") {}).electron.version'` (shell.nix follows unstable, so the two can drift).
- **Android build files:** release builds allow HTTPS only. Cleartext is allowed for `localhost` only, in the debug build's network security config. `android:allowBackup="false"`.
- **Electron:** `safeStorage`'s asynchronous methods only (the synchronous ones are deprecated in 45 and removed in 46). Every Electron test runs with `--password-store=basic`, so tests never touch the developer's keyring, and with `chromiumSandbox: true` (Playwright's `_electron.launch` otherwise adds `--no-sandbox` on Linux). Electron is found through `createRequire(<apps/client>/src-electron/package.json)('electron')`, which gives nixpkgs' Electron locally (npm's `electron` package honours `ELECTRON_OVERRIDE_DIST_PATH`) and npm's on CI; nothing outside `src-electron` can resolve `electron` on its own. The main process's dev flag is `import.meta.env.QUASAR_DEV`.
- **Formatting:** generator output is committed untouched, then formatted (Prettier) in the following "fit" commit. Build output inside generated folders (e.g. `src-capacitor/android/app/src/main/assets/`, Gradle's `build/`) is never linted: `apps/client/.prettierignore` lists it, and the client's Prettier scripts read it alongside `.gitignore`.

## Review Focus

1. **Two columns with the same name, or rows read as arrays.** Android's plugin returns each row as an object keyed by column name, so a query returning two columns named `id` would silently lose one, and `values` rows depend on key order. The store contract fails any query whose result has duplicate column names, and the Capacitor driver's tests pin the column order it produces (Tasks 2 and 5).
2. **A batch that fails halfway on Android.** The second of three statements throws: the driver rolls back, rethrows, and the first statement's row isn't there; a later batch still works (Task 5).
3. **Paths outside the app's UI files through `tdl://app`.** `..`, `%2e%2e/` and `%2F` forms, a different host (`tdl://other/index.html`), and the main-process files (`electron-main.js`, `electron-preload.cjs`, `package.json`) answer 404 and are never read (Task 7).
4. **IPC from anything but the app window's main frame.** A message from an iframe, even one at `tdl://app/`, or from a page the window was steered to, is refused; the window can't navigate away from `tdl://app` or open new windows, and links to other sites open in the system browser. The dev server's origin is accepted only in dev builds (Task 7).
5. **SQL from the window reaching the file system.** `ATTACH`, `DETACH`, `VACUUM` and `PRAGMA`s the store doesn't use are refused before they reach SQLite on desktop, and every `tdl://app` response carries a strict Content Security Policy (Task 7).
6. **A token that can't be read back.** Android's secure storage throwing on `get` (e.g. its Keystore key is gone) and desktop's `safeStorage` refusing to decrypt are both treated as "no token": the app shows the stored tasks and asks to log in again, as after an expired session, and never crashes at start (Tasks 5 and 7).
7. **Credentials and origins.** Token platforms send no `credentials: 'include'`; a token is stored only after `me()` succeeds; the server refuses sign-up and every sign-in from an `Origin` outside its own and `APP_ORIGINS` (Tasks 1 and 3).

### Task 1: The server trusts the apps' origins, and checks them itself

Better Auth checks `Origin` on email sign-in and sign-up even without cookies (its first-login CSRF check, `formCsrfMiddleware` in 1.7), so those from `https://localhost` or `tdl://app` are refused with 403 `INVALID_ORIGIN`. Its username sign-in (`/sign-in/username`, which the app uses whenever the identifier has no `@`) has no such check, so it accepts any origin. Login CSRF is already blocked by JSON-only bodies, CORS and `SameSite=Lax` cookies; the server's own check is defence in depth, one rule for every sign-in route. Bearer sign-out has no cookie and isn't checked. Better Auth's `matchesOriginPattern` matches `tdl://app` and `capacitor://localhost` as plain strings (checked in 1.7.20), so `trustedOrigins` can be a plain array.
